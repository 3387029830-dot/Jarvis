# Product Charter

## 1. Product definition

Jarvis is a voice-first immersive desktop application that helps a user explore questions across fields, preserve personal beliefs, discover connections, and observe changes in their own cognition.

It is not an answer engine with a prettier skin. It is a persistent cognitive environment.

## 2. Target user state

The initial user is in a period of broad curiosity and wants to understand subjects such as:

- finance and economic systems;
- psychology and human behavior;
- philosophy and cognition;
- society, institutions, power, freedom, and identity;
- stories and fictional characters as lenses for real-world questions.

The user often has incomplete thoughts and does not want to manually classify them before speaking.

## 3. Core job to be done

“When I become curious about something, let me immediately discuss it in a space that remembers what matters, connects it to other domains, and shows how my understanding changes over time.”

## 4. Product promises

### Presence

Jarvis feels available and continuous rather than like a disposable blank chat.

### Exploration

Jarvis does not only produce answers. It exposes assumptions, alternative frames, cross-domain connections, uncertainty, and questions worth continuing.

### Continuity

Important thoughts survive the session and reappear naturally when relevant.

### Ownership

The user owns the archive. Data is local-first, inspectable, exportable, and optionally synchronized to Obsidian.

### Self-understanding

Jarvis helps the user notice recurring questions, changing beliefs, and patterns of attention. It does not diagnose or define the user.

## 5. Non-goals

- Competing with frontier models on raw general intelligence.
- Becoming a universal automation platform in the first stage.
- Automatically categorizing every sentence into a productivity system.
- Replacing professional medical, financial, or psychological advice.
- Producing an authoritative personality profile.
- Maximizing time spent in the app through artificial engagement.

## 6. Product loop

```text
Curiosity
  → voice/text conversation
  → cross-domain exploration
  → candidate questions, concepts, beliefs, and connections
  → user confirmation
  → cognition map update
  → future retrieval and belief revision
  → self-reflection
  → new curiosity
```

## 7. First release success criteria

The foundation release succeeds when a user can:

1. open Jarvis and immediately understand what is still in progress;
2. hold a key and ask a question naturally;
3. receive a spoken and written answer with visible voice states;
4. see at least one useful cross-domain connection during the conversation;
5. confirm a personal belief or insight for saving;
6. find it in the cognition map;
7. revisit the same topic later and create a visible belief revision;
8. export the confirmed record to Obsidian without losing the original source.
