# Jarvis 简体中文文案规范

## 目的

简体中文是 Jarvis 正式产品界面的默认语言。英文只用于 Jarvis 品牌、代码/API 名称、无法自然翻译的专有名词，以及弱化的辅助技术标签。

## 基本原则

- 用户操作、导航、状态、错误、帮助、空状态和隐私说明必须优先使用简体中文。
- 文案应当平静、具体、诚实，不夸大尚未存在的能力。
- 不使用企业后台、效率工具或通用客服式表达。
- 不把每个问题写成任务，不使用“进度”“产出”“完成率”等管理语言描述认知探索。
- 不暗示模型正在后台自主思考、记忆或演化。
- Mock、未接通和未保存的状态必须明确写出。
- 认知候选不能写成已确认的人格、信念或事实。

## 术语约定

| 英文概念            | 正式中文     | 使用说明                                        |
| ------------------- | ------------ | ----------------------------------------------- |
| Presence            | 此刻         | 导航使用“此刻”；`Presence` 只可作为弱化辅助标签 |
| Conversation        | 对话         | 未实现时标记“后续开放”                          |
| Constellation       | 星图         | 指个人认知关系空间，不称为仪表盘                |
| Evolution           | 演变         | 指观点与理解随时间变化                          |
| Archive             | 档案         | 不是任务历史                                    |
| cognition candidate | 认知候选     | 必须提示待确认                                  |
| reduced motion      | 减少动态效果 | 状态反馈保留，去除非必要动画                    |

## 文案结构

- 操作标签使用动词短语，例如“继续探索”“暂存问题”。
- 状态说明直接描述事实，例如“当前不会录音”。
- 错误信息同时说明发生了什么、当前是否保存、用户能做什么。
- 空状态提供方向，但不制造焦虑或虚假进度。
- 中文正文默认使用全角中文标点；代码、类型名、路径和命令保留原样。

## 工程约定

- 正式产品静态文案集中在 `apps/desktop/src/renderer/src/copy/zh-CN.ts`。
- 文案目录通过 `ProductCopy` 约束完整结构，禁止在组件中建立另一套独立默认文案。
- 动态内容通过 typed view-model 进入视图，不混入静态文案目录。
- 日期与数字使用 `Intl` 和 `zh-CN` locale，不手写英语月份或不稳定格式。
- 开发 showcase 可以保留 Button、Dialog、CSS variables 等组件/API 名称，但解释性内容优先中文。

## 评审检查

- 页面是否存在只有英文才能理解的主要操作？
- 是否把未实现功能写得像已经可用？
- 是否明确区分真实功能、Mock 数据与未来能力？
- 是否在中文长文本和中英文混排下验证行宽、行高和换行？
- 是否避免诊断、人格定性和未经确认的认知结论？
